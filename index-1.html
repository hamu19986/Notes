Part 1 — HTML structure & content

Lvl 1 Absolute Beginner

WHAT? HTML (HyperText Markup Language) is the skeleton of every web page — it describes content, not looks.

WHY? Browsers can only render a page if the content is wrapped in tags they understand.

<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8">
    <title>Page Title</title>
  </head>
  <body>
    <!-- visible content goes here -->
  </body>
</html>

📌 REMEMBER: <!DOCTYPE html> must be the very first line — it tells the browser "render in modern standards mode."

⚠️ COMMON TRAP: Forgetting <head> vs <body> — nothing inside <head> is visible on the page.

Core structure tags

<head>Metadata, title, links to CSS/JS<head><title>Home</title></head>Putting visible text inside it
<body>Everything the user sees<body><h1>Hi</h1></body>Only one <body> per page
<h1>–<h6>Headings, biggest to smallest<h1>Title</h1>Skipping levels (h1 → h4) breaks accessibility

Part 7 Asynchronous JavaScript

Request→ Promise→ Resolve / Reject→ await→ Result 
// Promise style
fetch("/api/user")
  .then(res => res.json())
  .then(data => console.log(data))
  .catch(err => console.error(err))
  .finally(() => console.log("done"));

// async/await style (cleaner)
async function loadUser() {
  try {
    const res = await fetch("/api/user");
    const data = await res.json();
    console.log(data);
  } catch (err) {
    console.error(err);
  }
}

📌 REMEMBER: await only works inside an async function (or a top-level module).

⚠️ TRAP: forgetting await — you'll log a pending Promise object instead of the actual data.

Part 8 Advanced JavaScript

WHAT — Closure: a function that "remembers" variables from where it was created, even after that outer function has finished.

function makeCounter() {
  let count = 0;
  return () => ++count; // remembers `count` forever
}
const counter = makeCounter();
counter(); // 1
counter(); // 2

📌 REMEMBER: closures power private state, memoization, and event-handler factories.

3. To-Do List

An array of tasks is the "source of truth"; every change re-renders the list from that array.

<script>
const todos = [];
function render() {
  list.innerHTML = "";
  todos.forEach((t, i) => {
    const li = document.createElement("li");
    li.textContent = t;
    li.onclick = () => { todos.splice(i, 1); render(); };
    list.append(li);
  });
}
add.addEventListener("click", () => {
  if (!task.value.trim()) return;
  todos.push(task.value); task.value = ""; render();
});
</script>

  if (/^[0-9+\-*/.\s]+$/.test(disp.value)) disp.value = eval(disp.value);
});
</script>

⚠️ Real apps should avoid eval() — this demo restricts input to digits/operators first to stay safe.

MISTAKES

Part 6 — Don't Make These Stupid Mistakes

✗ <p>Hello

✓ <p>Hello</p>

Unclosed tags let the browser guess where an element ends — layout breaks unpredictably.

✗ <p><div>x</div></p>

✓ <div><p>x</p></div>

Block elements can't legally nest inside inline/paragraph elements.

✗ Two elements with id="box"

✓ One id, or use a shared class

IDs must be unique — getElementById and CSS #id only ever find the first one.

✗ if (x = 5)

✓ if (x === 5)

Single = assigns, it doesn't compare — a classic silent bug.

✗ function add(a,b){ a+b; }

✓ function add(a,b){ return a+b; }

Without return, a function silently gives back undefined.

✗ const b = a; b.push(1);

✓ const b = [...a]; b.push(1);

b = a copies the reference, not the array — both variables point to the same data.

✗ Fighting styles with more !important

✓ Understand specificity, restructure selectors

Stacking !important just moves the war one level up — it doesn't fix the cause.

✗ Using margin to create inner space

✓ Padding = inside the border, margin = outside

Confusing the two causes layout gaps that "should" be there and aren't (or vice versa).

✗ Swapping justify-content and align-items

✓ justify = main axis, align = cross axis

They only look interchangeable in a row layout — switch to column and it's obvious they're not.

✗ Forgetting box-sizing: border-box

✓ Set it globally: * { box-sizing: border-box; }

Without it, padding/border silently add to your declared width.

✗ el.innerHTML = userInput

✓ el.textContent = userInput

Untrusted HTML injected via innerHTML is a textbook XSS vulnerability.

✗ const data = fetch(url).json();

✓ const data = await (await fetch(url)).json();

Skipping await gives you a pending Promise, not the resolved value.

✗ Attaching a listener to every list item

✓ One delegated listener on the parent

Per-item listeners don't work on items added later and don't scale — delegate instead.
